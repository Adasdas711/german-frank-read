# Немецкий по Франку

Автономная читалка немецких книг с русскими подсказками и отдельный сборщик `.fbook`.

## Запуск

Откройте **index.html** в современном Chrome или Edge. Установка, сервер и интернет для чтения не нужны. `fbook-builder.html` — отдельный самодостаточный сборщик. Для перехода между ними положите оба файла рядом. На телефоне можно использовать обычный статический хостинг; данные остаются в IndexedDB браузера.

Встроены **три демонстрационных отрывка книг**, а не полные книги: «Бременские музыканты» (3 отрывка), «Красная Шапочка» (2) и «Превращение» (1). Они честно помечены «Автотекст». Полные проверенные издания в поставку не включены: нужна человеческая сверка с источником. Исходники демонстраций — `src/demo-source.json`, отдельные файлы — `books/`.

## Возможности

- Чтение по Франку с повторением чистого текста, чистый текст, параллельный перевод по предложениям.
- Оглавление, переход клавишами ← →, автоматическое сохранение места, завершение книги.
- Карточка слова: лемма, перевод, IPA, подсказка фразы, сохранение контекста.
- Офлайн eSpeak NG в Worker: IPA → фонемы → WAV → Web Audio; системный немецкий голос как альтернатива. Первый запуск синтезатора требует распаковки и компиляции WASM.
- Загрузка и перетаскивание `.fbook` версии 2, проверки ZIP, CRC-32, структуры, IPA, ссылок, статистики и переводов. Обновление книги по UUID и revision сохраняет данные.
- Слова с поиском, группировкой по книге, CSV и текстовым экспортом Anki с подколодами и выделением формы в контексте. Метка «в Anki» обозначает экспорт, а не подтверждённый импорт в Anki.
- Темы, шрифты Literata / Golos Text / системный, размер и скорость речи.
- Резервная копия JSON либо ZIP с книгами. Импорт объединяет слова, сохраняет более свежий прогресс и отдельно спрашивает о замене настроек. Данные импортируются транзакционно.
- Удаление книги сохраняет прогресс и слова; очистка всех данных требует подтверждения.

## Сборщик

1. Загрузите `book.source.json` из ТЗ (либо несколько частей по порядку) или вставьте JSON. Кнопка «Пример» открывает демонстрационный исходник.
2. Заполните паспорт: название, автор, уровень, источник, лицензия.
3. Загрузите исходный PDF с текстовым слоем. Удалите колонтитулы из извлечённого текста и сравните слова. Красные слова отсутствуют в исходнике, зелёные — лишние. Пунктуация проверяется вручную. OCR не выполняется.
4. Создайте IPA. Личные исправления имеют приоритет над допустимой IPA от ИИ и eSpeak. Свяжите формы со словарными леммами вручную, где автоматическое точное сопоставление не сработало. Можно импортировать и экспортировать личный словарь IPA.
5. Проверьте отрывки: подсказки, смысл, переводы, произношение. Есть добавление/удаление подсказки, разделение и объединение кусков, переход к сомнениям, отмена правки и применение JSON переразметки с проверкой неизменности оригинала. Для замены оригинала выделите правильный фрагмент в поле текста PDF и используйте «Взять из PDF».
6. Скачайте `.fbook`. UUID сохраняется в черновике, revision увеличивается. Архив проверяется обратной распаковкой. Метка «Проверено» доступна только при проверке всех отрывков, отсутствии сомнений, совпадении последней сверки слов и заполненном чек-листе.

Черновик сохраняется автоматически в IndexedDB и скачивается как `.fbook-draft.json`. Сборщик не обращается к ИИ и не отправляет текст в сеть.

## Разработка

Node.js 22.12+ (проверено с 24.19.0). Из корня репозитория:

```sh
npm ci --cache /tmp/npm-cache
npm run build
npm test
npm run typecheck
npm run test:e2e
```

Сборка обновляет `index.html` и `fbook-builder.html` в корне. Шрифты, скрипты, ZIP-библиотека, PDF Worker и сжатая WASM встроены; внешних зависимостей во время работы нет. `npm run dev` запускает Vite; после первой сборки страницы разработки доступны как `/reader-dev.html` и `/builder-dev.html`.

`npm run test:e2e` использует установленный `/usr/bin/chromium`, временный HTTP-сервер на 127.0.0.1:4173 и два независимых контекста браузера. Проверяет интерфейс, звук, прогресс после перезагрузки, Anki, перенос резервной копии, экран телефона, извлечение PDF, сборку и импорт книги. Проверяет отсутствие HTTP-запросов приложения, кроме навигации на сам HTML. `TEST_FILE_URL=1 npm run test:e2e` проверяет file://, если политика браузера разрешает локальные файлы.

Исходники модулей — `src/`; общие проверки и упаковка — `src/core.ts`, конвейер сборки книг — `src/builder-core.ts`. Повторная генерация демонстраций: `node scripts/demo.mjs`, затем `npm run build`.

## Проверка и ограничения

- Цель ТЗ ≤4 МБ пока не достигнута: читалка ~12,7 МиБ, сборщик ~14,1 МиБ. Используется готовая многоязычная WASM eSpeak NG; для уменьшения нужна отдельная немецкая сборка. Исключение озвучки ради размера не применялось.
- Интерфейс проверен в Chromium на ширинах 390, 834 и 1440 пикселей. В данной облачной среде корпоративная политика Chromium блокирует `file://`; браузерные проверки выполняются по локальному HTTP. Сохранение локального HTML после полного перезапуска браузера и поведение Safari/iOS требуют проверки на целевых устройствах. Резервные копии особенно важны при переносе файла.
- Нет полных книг с человеческой проверкой, Zopfli, OCR и `.apkg`. PDF со сложными внешними CMap/шрифтами может потребовать текстовый исходник вместо PDF. Эти возможности не имитируются.
- Сверка PDF — по словам с ограниченным поиском выравнивания, поэтому длинные перестановки показываются как пропуски и добавления. Пунктуация и смысл проверяются человеком. Исходник можно править в JSON; ручная сверка не заменяется автоматической отметкой.
- Лимит книги и распакованного ZIP — 32 МБ, PDF — 64 МБ, JSON исходника — 16 МБ. ZIP-копия большого собрания свыше 32 МБ не поддерживается; сохраните данные JSON и книги отдельно.
- Акустическое качество IPA-конвертации не подтверждено человеческим прослушиванием 100 слов; проверены генерация и декодирование реального WAV, автоматическая совместимость таблицы на формах демонстраций. Время запуска на среднем телефоне не измерено.
- Anki-файл проверен на структуру и содержимое; импорт в установленную настольную Anki в этой среде не выполнялся.
